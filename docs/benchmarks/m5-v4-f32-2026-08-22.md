## Protocol

Fresh process per run, 12 runs per cell (first 2 discarded as warmup, median of
remaining 10). Lengths map to campaign latent frames 45/112/255/333/489/685 via
`--seconds {1.8,4.48,10.2,13.32,19.56,27.4}`. Timings are the pipeline's
`[timing] rf=/codec=` stage walls (device work incl. sync). Deviation vs RTX
campaign: one chain of 12 fresh processes instead of 5 sessions x (2+10).

Raw logs: `target/bench_results/`, driver `target/bench/sweep.sh`,
aggregator `target/bench/aggregate.py`.

## Observations

1. RF dominates; codec decode is 20–50 ms across all lengths.
2. Shape-dependent non-monotonicity: the 45-frame cell is slower than 112-frame
   in every voice (suspected small-m matmul tiling/padding on Metal); the
   333-frame cell costs more than 489-frame for design/clone. Per-shape CubeCL
   autotune selections are the likely cause and are cached after first use.
3. Voice topology cost: batch-3 routes (design/clone, effective rows 8) are
   ~30% slower than text-only (rows 6) at short lengths; the gap widens again
   at 685 frames (design/clone ≈ 1.55–1.62x of text).
4. Model load adds ~2.5–3.5 s of process wall before steady-state synthesis.
5. Rough context against the RTX 5070 Ti Laptop F16 campaign (different
   precision and inputs, not a controlled comparison): M5 F32 RF is ~19x
   slower at 45 frames and ~9x at 685 frames (text).

Findings:

1. RF sampling: PyTorch MPS is faster in every cell (1.25–4x). MPS's native
   Metal matmul path beats burn/CubeCL matmul on M5, especially at small m.
2. Codec decode: the fused WGSL codec is nearly length-independent
   (~20–50 ms) while MPS decode scales linearly to ~3.5 s at 685 frames —
   a 70–170x WGSL advantage that carries the E2E win at practical lengths.
3. E2E crossover sits around 100–200 latent frames; beyond ~10 s of audio
   WGPU wins every voice mode.
4. Runtime load: PyTorch ~5.9 s vs Rust pipeline ~2.5–3.5 s process wall.
5. All MPS sessions produced identical audio hashes within a cell.

## RF optimization on M5 (2026-08-22, same day follow-up)

Profiling with `--features profile` + `IRODORI_RF_DETAIL_PROFILE=1` showed the
projection/MLP matmul stack dominates RF (91% of layer time at 45 frames,
75% at 255), and the hand-written t64 GEMM kernels reach ~1.9 TFLOPS where
burn eager matmul sits near ~0.3 TFLOPS on Metal. The kernels were gated to
`sequence ∈ [100, 685]` and `batch ≤ 2`, leaving 45-frame requests and every
batch-3 voice-design/clone forward on the slow path (`DIT_MAX_BATCH=2` while
voice modes run `[3,3,1,1]` topologies).

Change: admit `sequence >= 13` and `batch <= 3` across the dit projection /
MLP expand / contract(-residual) t64 kernels plus the packed wo/w2 row-major
cache policies (`dit_projection_t64.rs`, `attention.rs`, `feed_forward.rs`,
`dit_mlp_contract_residual.rs`, `timestep_condition.rs`). Tests updated;
525 lib tests pass; clippy clean on changed files.

Correctness (full-pipeline A/B, PCM16):

| condition | result |
|---|---|
| text/design/clone @255f, 40 steps | bit-identical to pre-change output |
| text @45f | max diff 1/32768 FS, SNR 97 dB (f32 summation order) |

40-step RF medians (12 runs per cell, warmup 2 discarded):

| cell | before | after | speedup | PyTorch MPS 40-step |
|---|---:|---:|---:|---:|
| text @255f | 6,942 ms | **6,112 ms** | 1.14x | 5,241 ms (E2E 6,529) |
| clone @255f | 13,264 ms | **8,804 ms** | **1.51x** | 6,949 ms (E2E 8,639) |
| design @255f | 13,107 ms | **8,641 ms** | **1.52x** | not measured |
| text @685f | 34,863 ms | 34,568 ms | 1.01x | not measured |
| text @45f | n/a | 1,989 ms | -26% vs pre-opt 4step-scaled | not measured |

At realistic 40 steps the optimized WGPU build reaches E2E parity/superiority
against PyTorch MPS at 255 frames: text 6,147 ms vs 6,529 ms (WGPU wins),
clone 8,834 ms vs 8,639 ms (within 2%).

Remaining bottleneck: long-length text RF is attention-bound (burn SDPA
fallback; native fused SDPA configs only exist for sequences {13, 25, 50},
joint-KV WGSL paths still cap batch ≤ 2). Extending those is the next lever.

## Reproduction

```bash
bash target/bench/sweep.sh          # ~23 min on M5
uv run target/bench/aggregate.py    # prints table, writes summary.json
```

First-time setup: download v4-Small + tokenizer + DACVAE `weights.pth`, then
`uv run scripts/convert_dacvae_weights.py --pth <pth> --output
target/v4_dacvae_weights.safetensors`. Building requires `VULKAN_SDK` to be set
on macOS because the locked `cubecl wgpu-spirv` feature gates on it; no Vulkan
runtime is used on Metal.

PyTorch side: clone `Aratako/Irodori-TTS` to `../Irodori-TTS`,
`git checkout 9f19d9a`, then
`bash target/bench/sweep_mps.sh` (~20 min) and aggregate from
`target/bench_results_py/*.json`.
