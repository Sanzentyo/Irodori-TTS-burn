# WGSLPack review and corrections — 2026-10-13

The original stack had already been merged before this review. The corrections
below are developed on separate branches and must pass a final diff review and
validation before their own PRs are merged.

The starting points are Irodori `74e86d1` (WGSLPack implementation `cdd8e90`) and
standalone WGSLPack `ed2070d`. This is a manual code review by the implementing
agent, not an independent human approval. The review covers the new format,
writer, borrowed/file/owned adapters, metadata and precision checks, WGSL layout,
benchmark and oracle replay scripts, and their synthesis/builder call sites.
The synthesis voice identity and attention/projection cache boundaries were
also inspected. It is not a new line-by-line audit of every historical kernel
experiment included in the preceding stack.

## Findings and fixes

### P2: documented reader-only configuration fails its doctest

`cargo test --no-default-features --doc` failed with E0432 because the README
unconditionally imported the feature-gated `Layout` and `TensorSpec`. The default
feature check passed and therefore missed the supported reader-only case.

The README now provides an allocation-free reader example and gates the writer
example on `alloc`. Independent wire fixtures exercise borrowed scalar access,
truncation and invalid offsets without the writer feature. Reader-only nextest
runs use `--no-tests fail` so an empty suite cannot be mistaken for validation.
Both copies of the standalone crate receive the same change; CI stays removed.

### P2: cached parameter verification is not bound to the replayed file

The load benchmark stored a parameter digest but no checkpoint-file digest.
The replay script subsequently hashed whatever file was currently at the same
path and rebound the oracle to it. Replacing that file could therefore reuse
the old full-parameter verification. A short synthesis fixture need not exercise
every changed parameter, such as duration-predictor weights.

A regression fixture with a stub model runner reproduced acceptance of a
same-length replacement before the fix. The benchmark now records checkpoint
SHA-256 values before measurement, associates every case with its input, and
checks both inputs and the executable again before publishing the campaign.
Hashes are outside the model-load timing. The replay verifies those identities
before creating an output directory or launching GPU work, then retains the
existing strict per-file hash check in the synthesis validator.

Campaign schema 2 is required for replay. Historical campaigns without recorded
file identities must be measured again; no file identity is retroactively
inferred from their parameter hashes. Normal oracle rebinding still preserves
all tensor bytes and records original-checkpoint provenance.

### P2: non-Linux load campaigns fail while summarizing optional RSS

`bench_checkpoint_load` deliberately reports `peak_rss_kib: null` outside Linux.
The Python driver passed those values to `statistics.median`, failing with
`TypeError` after the measurements completed. A runner fixture returning the
documented optional metric reproduced this error. RSS summaries now retain
`null` when unavailable; required timing metrics remain mandatory.

## Verification

The Python regressions reproduced three assertion failures and one missing-field
error before the identity fix; the unchanged successful-replay case passed.
The additional RSS test reproduced a `TypeError`. All seven regressions pass
after the fixes, including binary replacement, rejection before model execution,
optional RSS and unchanged oracle payload bytes. Resource warnings are also
treated as errors.

Standalone nextest passes nine tests with default features and two with no
default features. Both feature configurations pass their two doctests. Formatting
and standalone Clippy pass. Workspace Clippy passes with `cli,synthesis,
packed-export,worker,http-server,lora,profile`. Cargo reverse dependencies remain
`wgslpack -> irodori-tts-burn`; neither manifests nor production Rust/WGSL changed.
The preceding 63-test integration slice and GPU layout checks are reused for
unchanged implementation paths, rather than reported as newly rerun tests.

The schema-2 MF campaign completes all 16 fresh-process loads: two repetitions
of the original and native loaders on RTX/Intel in FP32/FP16. Recorded input and
binary hashes are unchanged at completion. The full-parameter digest agrees in
each precision. Fresh two-second MF replay is bit-identical for both latents and
audio in all four adapter/precision combinations. These runs validate evidence
capture; the original four-repetition campaign remains the performance baseline.
The later optional-RSS correction only changes summaries when RSS is unavailable;
the Linux measurement path and replay implementation are unchanged.

## Final diff review

The final pass checks that required hashes cannot be silently synthesized from
historical evidence, that rejection precedes oracle/output creation, and that
the successful replay preserves every oracle payload byte. Optional RSS does
not weaken required timing metrics. The two format copies are byte-identical,
and the public `alloc` boundary remains unchanged. Production kernels, model
weights and wire bytes are unchanged. No further actionable finding remains in
the reviewed changes. The existing unrelated benchmark-document edit is excluded.

The repository instructions now require review, resolution of actionable
findings, and relevant verification before subsequent merges.
